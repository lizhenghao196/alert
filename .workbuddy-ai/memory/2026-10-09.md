## 历史数据页 · 第二轮修改（8 条反馈）

### 1. 两个模式共用查询条件
- 原状态：模式一 `systemId` 空、模式二默认 `LMP`，两边不一致。
- 改法：条件状态**上提到 `AppHistory`**（`teamName` / `systemId` / `dateRange`），
  两个模式只做受控读写（`HistoryModeProps`，定义在 `history/query.ts`）。
  默认值统一取模式一那套：组别「不限定组别」、系统空、日期范围最近 30 天。
- 新增 `src/history/query.ts`：`SYSTEM_GROUPS` / `DEFAULT_GROUP` / `normalizeSystemId`
  / `HistoryQuery` / `defaultRange` / `rangeOf` / `buildClosedParams` / `HistoryModeProps`。
  **`mode1/groups.ts` 已删除**，引用改到 `history/query.ts`。
- 新增 `src/history/calendar.ts`：`fmt` / `parse` / `sameDay` / `monthCells` / `WEEKDAYS`
  / `todayString` —— 模式一的 DateRangePicker 与模式二的 DateField 共用，去掉重复实现。

### 2. 切换模式调一次接口
- 两个模式常驻挂载（切换只切显隐、各自保留结果），靠 `active: boolean` prop：
  `useEffect(() => { if (active) runQuery() }, [active])`。
  active 翻转即重查，所以首次进入模式一也会自动查一次（不再是空态等待点查询）。

### 3. 删掉模式二顶部那一行
- 删掉「历史关单查询  /proxy/event_mgm/event/query/closed」整行
  （`HistoryMode2.tsx` 的 `.hist2-bar__head` + mode2.css 里对应两条样式）。

### 排查：刷新历史数据页时模式一接口请求两次
- 原因：`main.tsx` 里包了 `<React.StrictMode>`。**React 18 的 StrictMode 在 dev 下
  会「挂载 → 卸载 → 再挂载」跑一遍**，用来暴露不幂等的 effect，所以挂载时的
  自动查询被触发了两次。**生产构建不会**（React 的 prod 版里 StrictMode 对
  effect 双调用是 no-op）。
- A/B 实证（在用户 5173 的 dev server 上用 `page.route` 数请求，脚本
  `.workbuddy-ai/tmp/count-hits.js`）：
  - 带 StrictMode → `REQUESTS=2`
  - 临时把 main.tsx 换成 `React.Fragment` → `REQUESTS=1`
  - 还原 StrictMode → `REQUESTS=2`
  （临时改动已还原，`tsc -b` 通过。）
- 生产侧旁证：`dist` 产物里既没有 `React DevTools` 也没有 `doubleInvoke`
  （都是 React dev 版专有标志）→ 确认打进去的是 React 生产版 → 生产只请求一次。
- 注意：StrictMode 只在**挂载**时双跑 effect，后续 update 不会。所以
  「切到模式二 / 切回模式一」各只请求一次；只有首屏模式一的挂载会翻倍。
  另外因为两个 effect 是背靠背同步跑的，`if (loading) return` 这道防重入挡不住
  （`setLoading(true)` 还没生效）。
- 若想让 dev 控制台干净，可在 effect 里加一个 ref 守卫（只在 dev 下少发一次），
  但会削弱 StrictMode 的提示作用 —— 未改，等用户决定。
- **生产实测确认（不是只靠推理）**：起了一个一次性静态服务器把 `dist` 当站点根
  （带 SPA 兜底，脚本 `.workbuddy-ai/tmp/prod-server.cjs`，端口 5223，验完已关），
  再用 playwright 加载 `/alert-screen/history/` 并数请求 →
  `mode1RequestCount: 1`、`mode1Mounted: 1`、`dateText: "2026-10-09 至 2026-10-09"`、
  `pageErrors: []`。**生产刷新确实只请求一次。**
- 附带经验：`playwright-cli run-code` 的沙箱里**没有 `require`**（想读本地文件会报
  `ReferenceError: require is not defined`）；要在本地跑生产构建，就起个静态服务器；
  另外 run-code 的返回值是带引号打印的，grep 时别锚 `^\{`。
  临时服务器别用 `vite dev`（用户会关），静态文件服务器更轻。
