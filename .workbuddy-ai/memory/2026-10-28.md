## 下拉面板被弹窗裁切（重要坑）

- 现象：靠底部的「告警是否恢复」展开后，选项面板被切成半截，第三个选项只露一点。
- 根因：面板在触发器下面 `position: absolute`，而弹窗表单区是 `overflow-y-auto`，
  超出可视区就被裁；面板还压不到 footer 之上。
- 修法（`V4Select` 重写定位部分）：
  1. `createPortal` 把面板挂到最近的 `<dialog>` 上——不能挂 body，`showModal()` 的 dialog 在
     top layer，body 里再高的 z-index 也会被它盖住；
  2. 面板改 `position: fixed`，坐标按触发器的 `getBoundingClientRect()` 算，彻底跳出祖先 overflow；
  3. 下方空间 < 180px 且上方更宽裕时整体翻到触发器上方（用 `bottom` 锚定，不用先量高度）；
  4. `maxHeight` 跟着可用空间收（上限 216px）；
  5. 监听 `scroll`（capture，覆盖弹窗内部滚动）和 `resize` 重新定位，别让面板和触发器分家；
  6. 点外部关闭要同时判 `rootRef` 和 `panelRef`（面板已经 portal 出去了）。
- 实测：1100×700 下滚到底再展开，3 个选项完整可见（面板 bottom 589 < 视口 700）；
  1100×560 时自动翻到上方；点选项、点外部关闭、键盘上下+Enter 均正常。

## 接口返回体改成 { code, message, result }

- 「未见处置自行恢复」改为「未经处置自行恢复」（`RecoverStatus` 类型 + 选项数组 + 默认值一起改）。
- `closeAlert()` 现在从 `message` 取提示文案（兼容旧的 `msg`），空/结构不符兜底「告警已关闭」。
- 额外加了 `result === false` 的保护：业务失败时把 message 当 ApiError 抛出，弹窗内红字提示、
  不关窗、不刷新、不弹绿勾——否则后端明确失败也会显示成功。
- 错误文案统一：`ApiError` 的 message 本身就是完整句子（HTTP 错误自带「请稍后重试」），
  弹窗 catch 里对 ApiError 原样显示，只有网络层 TypeError 才换成「提交失败，请稍后重试。」。

## 下拉列表滚不动的回归（portal 改造的副作用）

- 现象：告警原因类别 15 项，列表被裁到 216px 但滚不动。
- 根因：`maxHeight` 写在了外层（`position: fixed` 的浮层）上，内层滚动容器写的是 `max-h-full`。
  外层高度是 auto，百分比 `max-height` 解析成 `none`，内层因此没有自己的高度约束、不会滚动；
  内容超出后被外层的 `overflow: hidden` 直接裁掉。
- 修法：把 `maxHeight` 从外层挪到内层滚动容器（inline style），外层只留 `overflow: hidden` 收圆角。
- 实测：scrollHeight 505 / clientHeight 216，滚轮滚到 182，键盘 ↓×12 跟到 250 并选中「软件产品缺陷」。
- 教训：给滚动容器设 max-height 必须设在一个高度确定的元素上，别指望 `max-h-full` 穿透 auto 高度的父级。

## 关单返回体是嵌套的 { msg: { code, message, result } }

- 生产实际结构比之前以为的深一层：`{ msg: { code, message, result } }`，`code === 0` 才是成功
  （截图里 code 1002 表示"非待处理状态无法关闭"）。之前按扁平结构解析，取不到 message，
  业务失败也被当成成功、弹了绿勾。
- `api.ts` 新增 `unwrapCloseBody()`（有对象型 msg 就取内层，否则用外层，兼容扁平
  `{code,message}` 和更早的 `{msg:'字符串'}`）和 `toNumber()`（数字或数字字符串都收）。
- `CloseAlertResult` 改成 `{ ok, msg }`：`ok = code === 0`，拿不到 code 时按成功处理。
- UI：`V4Toast` 加 `tone: 'success' | 'warning'`，`code !== 0` 走 `.v4-toast.is-warning`
  （琥珀色边框 + TriangleAlert），`code === 0` 走绿勾。
- 两种情况的关闭/刷新行为一致：HTTP 200 就关窗 + `poll.refresh()`，只是提示样式不同。
- 实测：`{msg:{code:1002,message:'告警ID为...无法关闭和解决告警'}}` → 琥珀提示；
  `{msg:{code:0,message:'告警关闭成功'}}` → 绿勾提示，弹窗关闭。
