## 通读项目：alert-screen（告警实时观测大屏）

首次熟悉代码库，梳理如下（后续需求以此为基础）：

### 技术栈
- Vite 5 + React 18 + TypeScript 5 + TailwindCSS 3 + lucide-react 图标 + react-markdown（渲染报告）。
- `npm run build` = `tsc -b && vite build`；产物 `dist/`。
- base 固定 `/alert-screen/`，部署走 `deploy/nginx-alert-screen.conf`（root=/appdata/aiops_wk）。
- 接口是相对路径 `/ongoing-alerts-api/event/queryiongoingevent`（POST），nginx 反代到内网；
  dev 由 vite proxy 转发到 `http://49.51.194.37`。

### 四个版本并存（重要）
`src/main.tsx` 按 `window.location.pathname` 分流：
- 无前缀 → `src/App.tsx`（v1，卡片网格 + 顶部 KPI）
- `/v2/` → `src/v2/AppV2.tsx`（「值班终端」等宽风格，密集表格，独立 `--t-*` 令牌）
- `/v3/` → `src/v3/AppV3.tsx`（复用 v2 外壳，主体按严重度分区：异常瓦片 + 正常紧凑行）
- `/v4/` → `src/v4/AppV4.tsx`（异常优先自适应布局：左侧异常卡网格 + 右侧正常列表，按异常数切换密度）
注释明确：v2/v3/v4 是同一岗位的候选方案，定稿后删掉落选版本与分流逻辑。

### 数据与状态流（三版共用）
- `src/types.ts`：`Alert`（alertKey/systemId/href/msg/summary/code/type?/event_url?），
  `Selection`（teamName/systemId/frequency），`FREQUENCY_OPTIONS`，`TEAMS`。
  `code === 1` = 异常；「正常」按「非异常」计（含未知状态码）。
- `src/api.ts`：`queryOngoingAlerts`，返回 `{items, simulated}`；
  `X-Alert-Data-Source: mock` 响应头 → simulated=true（页面显示「模拟数据」徽标）。
- `src/hooks/useAlertPolling.ts`：核心轮询（generation 守卫、AbortController、60s 超时、
  localStorage 恢复上次条件）。frequency=0 表示仅查询一次。
- `src/hooks/useAlertSound.ts`（v1/v2/v3）：按「新出现的异常 alertKey」响一次。
  `src/v4/useV4AlertSound.ts`：改为「每个成功巡检批次只要有异常就响」。
- `src/storage.ts`（条件持久化）、`src/theme.ts`（light/dark，localStorage key
  `alert-screen.theme`，index.html 内联脚本防闪白）、`src/url.ts`（safeHref 防注入）、
  `src/motion.ts`（prefers-reduced-motion）。

### 约定 / 注意事项

  `<V4CommandBar>` 从 `<main>` 挪进来，`showLaunch` 时传 `null`）。
- 形态按用户选定的 B 案（**不做方框**）：整组 `align-self: stretch` 撑满 header，
  格子的 2px 下边框正好压在 header 底线上，看起来像一组页签；格间用 1px 竖线分隔；
  标签 10px、数字 16px 等宽；选中态 = 标签变色 + 2px 底线；数字保留各自的语义色
  （全部 = 正文色 / 异常 = 红 / 正常 = 绿），那是数据，不跟选中态走。
  之所以坚决不用方框：上一次把 40px 的 KPI 方框塞进 48px 的小字区就是「样式不统一」
  被退回的。
- 选中色：v2 用琥珀 `--t-amber`，v4 用主色 `--c-accent`（蓝，不是琥珀）。
- v4 的 `.v4-command-bar` 整个卡片外壳（border / radius / shadow / padding / grid）

  header 只剩它一个子元素，`space-between` 会把图标组甩到最左边。

### 3. 窄屏让位顺序（内容都还在，只是不上屏）

## 第二轮补充：并进 header 的形态被否，改回两个模式各自的原始外观

**上面「第二轮」那节里写的形态（一行装完、去方框、数字压成 16px 等宽、选中用底部
短线）已经被推翻，以本节为准。** 领导看后原话：「整合进去后好难看，模式一之前原来
是有阴影边框的，很有层次感，而且是分左右布局的……而且模式一和模式二之前选择的样式
都不一样了，你要结合原来的样式，可以微调，整合到 header 里面」。

结论：**「并进 header」这个动作保留，但外观各自照旧，只做容得下的微调。**

### v4（模式一）
- `.v4-command-bar` 恢复成原来那张卡片：grid 四列（计数 | 观测条件 | 实时状态 |
  修改条件）、`gap: 18px`、`padding: 0 8px 0 10px`、1px 边框 + 14px 圆角 +
  `--c-panel` 底 + `--shadow-card` 投影。
- `.v4-count` 恢复成方框：`min-width: 84px` / `height: 40px` / 圆角 10 / 两端对齐
  （左 12px 标签、右 22px 数字）/ 三个数字各自保留语义色（全部正文 / 异常红 / 正常绿）。
  选中与 hover 都是「描边 + `--c-raise` 0.75 的抬起底」——这是 v4 自己的选法。
- 唯一的功能性改动：条件列由 `minmax(260px, 1fr)` 松开成 `minmax(0, 1fr)`。header 里
  还要给右侧图标让位，窄了先压条件文字（span 有 overflow:hidden，自动最小尺寸为 0），
  不撑破卡片。
- `.v4-header` 高度 52 → **64px**：卡片 52px 居中，上下各留 6px，圆角和投影才落得下。
  实测 1600px 下卡片 1436×52 @ (20,6)，右侧图标组 124 宽，几何完全符合预期。
- `.v4-counts { align-items: center }`、计数格之间 6px，都按原样。

### v2（模式二）
- `.v2-kpi-cell` 恢复成方框：`min-width: 84px` / `height: 40px` / **直角**（v2 全直角，
  由 `.v2-root *{border-radius:0!important}` 兜底）/ 两端对齐 / 22px 数字。
  hover = 描边 + `--t-hover` 底；**选中 = 琥珀描边 + 琥珀 8% 淡底**（v2 自己的选法，
  跟 v4 的抬起底不是一回事）。
- 删掉上一版加的「格间 1px 竖线」和「选中 2px 底部短线」。
- `--t-masthead-h` 48px → **56px**（`3.5rem`），给 40px 方框留上下各 8px。贴顶表头
  `.v2-table th` 的 `top` 用的也是这个变量，一处改两边自动对齐。
- 实测 1440 / 1280 / 1100 / 1024 / 900 五档：header 高度恒为 56，无横向溢出；
  渐进隐藏规则（≤1200 时间戳 / ≤1040 副标题 / ≤880 状态文字）照旧生效。

### 教训（下次别再犯）
- 领导说「整合到 header 里面」指的是**位置**，不是把原来的视觉一起抹掉。两个模式各有
  各的设计语言（v4 = 圆角 + 卡片投影 + 抬起的选中态；v2 = 直角 + 琥珀描边的选中态），
  搬家的时候只搬位置，别顺手「统一」样式——统一了反而像退步。
- 「一行装完、去掉方框、数字压成等宽小字」那套是当时在选项里选的 B 案，看到实物立刻
  被否。这类「看起来更简洁」的方案对这套大屏反而丢层次。以后碰到形态题：**先按原样
  搬，再问要不要简化**，而不是先简化。

## 第三轮：assignee 原样展示 + 模式二底色对齐模式一 + 省略号加悬浮

### 1. assignee：字段里是什么就显示什么
- `V4Body` 的 `Assignee` **本来就没有解析括号**（一直渲染 `{row.assignee}` 原串）。这轮去掉的是
  悬浮提示里的「处理人：」前缀——连提示都直接用原值，不做任何改写。
- 真正的毛病在 CSS：`.v4-assignee` 原本是 `min-width: 0` + `overflow-wrap: anywhere`，最小宽度会
  塌成 1 个字，于是在可换行的 `.v4-card-actions` 里被挤成一条竖着的窄条，
  「刘兴贵1(19129506274)」被从中间掰成两行——看着就像被人处理过。
  改成 **`flex: none` + `max-width: 100%`**：整串不参与压缩，一行放不下就由 footer 的 `flex-wrap`
  整体换到下一行；只有「整串比卡片还宽」（多人处理人）才被卡到卡片宽度再断行。
  实测：普通值 133×17 单行完整、超长值 258×52 三行且不捅出卡片、页面无横向溢出。
- 记一笔：`min-width: min(max-content, 100%)` 在 Chrome 里会被**整条丢掉**（computed 还是 `auto`），
  内建尺寸关键字不能放进 `min()`。别再试这个写法。

### 2. 模式二（v2/v3）底色对齐模式一
- 只换 `--t-bg` 是不够的：米色发丝线压在冷灰底上反而显脏。所以整套中性色一起搬成 v4 那套：
  - 浅色：bg `247 248 250`（= `--c-canvas`）/ bg-alt `241 243 248` / rule `226 229 236` /
    rule-2 `208 213 222` / fg `28 34 48` / fg-dim `90 100 120` / fg-mute `100 108 126` /
    hover `237 240 245`。
  - 深色：bg `11 12 14` / bg-alt `18 19 23` / rule `36 38 43` / rule-2 `51 54 62` /
    fg `237 238 242` / fg-dim `158 163 176` / fg-mute `132 138 154` / hover `32 34 40`。
  - 投影 `--t-elev` 从暖改冷（`rgb(16 24 40 / .14)`），报告弹窗遮罩从暖黑改冷黑
    （`rgb(8 10 14 / .62)`）。
- **保留 v2 自己的琥珀 / 绿 / 红**（浅色 `140 97 16` / `26 116 72` / `170 40 28`，深色
  `224 163 46` / `79 180 119` / `228 86 72`）——那是它的身份，不是背景。换底后逐个复算了对比度，
  都还在 4.5:1 以上；`--t-fg-mute` 特意比 v4 的 `--c-fg-3`（只有 4.47:1）深一点，因为 v2 拿它画
  10px 的表头标签，AA 卡得更紧。
- 实测：v2 light = v4 light = `rgb(247,248,250)`；v2 dark = v4 dark = `rgb(11,12,14)`。
  v3 直接 import v2.css，自动跟着变；v1 走 `--c-*`，不受影响。
- **经验**：要做「跟另一版统一背景」，只改背景色一定不够，得把整套中性色（底/条纹/线/hover/字）
  一起搬过去，只把对方的强调色留在门外。

### 3. 省略号要能悬浮看全
- `.v4-progress-chip`（`max-width: 148px` + 省略号）补 `title={row.type}`。
- 顺手把告警单号也补了：`.v4-alert-key-text` 超长同样省略，`AlertKey` 的 `title` 改成
  `${key} · 在新标签页打开事件详情`（原来只有后半句），没有链接时给纯文本套一层 `title`。
- 同类位置还没做的：v2/v3 表格的单元格（`.v2-row td` 一律 `nowrap` + 省略号，摘要列最明显）。
  要的话可以统一给 cell 加 `title`，等确认。

## 第四轮：模式二的「观测条件」也挪到 header 右侧

## 第五轮：模式一 assignee 不再换行（三字名先保证，超了省略号 + 悬浮）

- 现象：assignee 有值时整串被 `.v4-card-actions` 的 `flex-wrap: wrap` 挤到第二行，卡片底部多出一行、
  高度还会抖。上一轮为了治「被挤成竖条」加了 `flex: none`，副作用就是这一条。
- 处理人的排布史（三条弯路都写在 v4.css 的注释里，别再走回去）：
  1. `min-width: 0` + `overflow-wrap: anywhere` → 最小宽度塌成 1 个字，被挤成竖条；
  2. `flex: none` + footer `flex-wrap: wrap` → 不塌了，但放不下就整体换行；
  3. 现在：**footer `flex-wrap: nowrap`** + 处理人 `flex: 0 1 auto; min-width: 0` +
     文字层 `.v4-assignee-text` 出省略号。一行钉死，超了截断，`title` 里是原值。
- 省略号必须挂在文字那一层：图标和文字都是 `.v4-assignee` 的 flex 项，裸文字节点是**匿名 flex 项**，
  挂不上 `text-overflow`——所以 JSX 里给文字包了一层 `<span className="v4-assignee-text">`。
- 左侧两个入口同步收紧，把宽度让给处理人：`.v4-card-links` `flex: none`、gap `9→7`，
  入口内 gap `5→4`，图标 `FileText 13→12` / `ExternalLink 12→11`，分隔线高 `11→10`，
  footer 列间距 `12→10`。合计省出 10px。

  - `欧阳明月3(13800138000)` 需要 143 → 省略号；三人处理人 359 → 省略号；
  - 1280（卡片 414）下连 4 字名 + 手机号也完整；1024/1920 与 1440 同宽同表现。
  - 所有宽度下 `wrapped` 均为 false，没有任何换行。
