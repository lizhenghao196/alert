## 历史数据模块 · 模式二表格高度：改成从视口实测（仅模式二）

用户反馈「下面还是有点空间，可以再往下放一点」。量了一下：1000px 视口下表格下方
还剩 **71px** —— 原因是我之前那个 `calc(100dvh - 190px)` 的预留值给多了
（实际只占 139px：header 64 + 上下 padding 36 + 底部「模拟数据」标签 39）。

**关键坑（重要，别再踩）**：想改成「自动吃满剩余空间」，先后试了两条 CSS 路，都不行：

1. `max-height: 100%` → **无效**。祖先链是
   `.history-root{min-height:100dvh}` → `main/panel/hist2-root{flex:1}`，
   容器高度是 **indefinite**（只有 min-height，没有 height），
   Chromium 不把 flex 派生高度当 definite，百分比解析成 `none`
   → 表格直接撑到内容全高 3468px，页面狂滚。
2. 量 `.hist2-body` 自己的 `clientHeight`（配 ResizeObserver）→ **自我循环**。
   同理：链上没有确定高度，`flex:1` 分不到空间，每个盒子都被内容撑开，
   于是 body 的高度就等于表格自己的高度，实测稳定在一个错误值 900。

**最终方案**（`HistoryMode2.tsx` 的 `useLayoutEffect`）：从**视口**往下算，绕开这条链：

```
可用 = window.innerHeight - 根节点下内边距 - body 之后的兄弟(底部标签) - body.top
```

- `body.top` 已经含了 header（含窄屏折行后的真实高度）、根节点上内边距、错误条，
  所以这几样都不用手工数 —— 这正是它比 `calc(dvh - 固定值)` 强的地方。
- 依赖 `[active, error, simulated]` + `window resize` 监听；不用 ResizeObserver
  （避免和表格高度形成循环）。
- ⚠️ 必须判 `body.offsetParent === null` 直接返回：两个模式常驻挂载、非当前的用
  `hidden`（display:none），隐藏时量到的 top=0 是错的。所以依赖里要有 `active`。
- 结果 `Math.max(240, Math.floor(avail) - 1)`：兜底 240，-1 是防溢出留的余量。
- 只设 `max-height` 不设 `height` → 行少时仍按内容收缩，不会撑出空白。

实测（用户 5173 dev server）：

| 视口 | header | 表格 | 底部剩余 | 页面滚动 |
|---|---|---|---|---|
| 1600×1000 | 64 | **860**（原 810） | 20（=根节点下 padding） | 无 |
| 1100×800（header 折行成 106） | 106 | 618 | 20 | 无 |
| 1600×1440 | 64 | 1300 | 20 | 无 |

## 历史数据模块 · 模式二前端分页（仅模式二）

领导要求：模式二做成分页效果，**前端分页**，总量约 300~1000 条。

新增：
- `history/components/Pagination.tsx` + `pagination.css`：Element `el-pagination` 形态的
  分页条（`共 N 条 | 每页 [20/50/100] 条 | ‹ 1 2 3 4 5 ··· 13 › | 前往 N 页`）。
  页码折叠规则**与 Element 的 pager 完全一致**（最多 7 格：当前页≤4 显示 `1..5 … 末`；
  当前页≥末-3 显示 `首 … 末-4..末`；其余显示 `首 … 当前±1 … 末`），
  导出成纯函数 `pageItems(page, pageCount)` 便于复用/测试。
- `history/components/DataTable.tsx`：新增可选 `wrapRef`（透到 `.aa-table-wrap`），
  翻页后把表格内部滚动条滚回顶部要用。
- `mode2/components/ClosedTable.tsx`：接 `wrapRef` 透传；`rows` 语义改为「当前页数据」。

改动：
- `mode2/HistoryMode2.tsx`：新增 `page` / `pageSize`（默认 **50**）状态，
  `pageCount` / `safePage` / `pageRows`（`useMemo` 切片）；
  **查询返回后 `setPage(1)`**；`page/pageSize` 变化时 `tableWrapRef.scrollTo({top:0})`。
- `mode2/mock.ts`：`TOTAL 96 → 640`、`GAP_MINUTES 97 → 60`（640×60min ≈ 27 天，
  贴近「最近 30 天」的量级）。

**关键设计：分页条放在 `.hist2-body` 之后，作为它的兄弟节点**（不是放在 body 里）。
因为表格高度是靠「body 之后的兄弟节点高度之和」扣出来的（见上一节），
放成兄弟后分页条的高度会被**自动扣掉**，表格高度逻辑一行都不用改。
副作用是表格从 860 → 820（分页条占 40px）。

⚠️ 边界处理（都实测过）：
- 跳页输入框清空后失焦 → 还原成当前页，**不能跳到第 1 页**（`commitJump` 里单独判空）。
- 越界输入（如 999）→ 夹到最后一页。
- 数据变少时当前页越界 → 用派生的 `safePage` 夹住，不额外 setState（少一次渲染）。
- 空态 / 未查询时不渲染分页条；高度实测的依赖里要带 `showPager`（`rows.length > 0`），
  否则分页条出现后表格不会缩。

实测（用户 5173 dev server，USE_MOCK=true）：

| 操作 | 结果 |
|---|---|
| 初始 | 50 行 / 共 640 条 / 第 1 页 / `1,2,3,4,5,…,13` / 上页禁用 / 表高 820 / 无页面滚动 |
| 表格滚到 400 后翻到第 2 页 | 行内容变了、`scrollTop` 归 0 |
| 跳末页 13 | 40 行（640=12×50+40）、`1,…,9,10,11,12,13`、下页禁用 |
| 每页改 20 | 20 行 / 32 页 / 回到第 1 页 / 表高 751 |
| 跳页框输入 7 | 第 7 页、`1,…,6,7,8,…,32` |
| 清空跳页框失焦 | 仍停在第 6 页（不跳第 1 页） |
| 末页时点「查询」 | 回到第 1 页 |

顺带确认：mock 的 640 行是**运行时**由 `buildRows()` 生成的，不是打包进 bundle 的静态数组，
所以条数从 96 涨到 640 产物只大了 ~2KB（451→453KB）。

### 追加：默认每页 20 条 + 结果 ≤20 条不显示分页

用户要求：默认每页 20；返回数量 ≤20 条时不显示分页功能。

- `mode2/HistoryMode2.tsx`：`DEFAULT_PAGE_SIZE` 50 → **20**；
  `showPager` 由 `rows.length > 0` 改为 **`rows.length > pageSize`**。
  ⚠️ 写成 `> pageSize` 而不是写死 `> 20`：用户把每页改成 100 时，
  一页能装下同样不该显示分页（保留意图而不是字面值）。
- 边界实测：15 条 / **20 条 → 不显示**分页；**21 条 → 显示**分页（第 2 页只有 1 行）。

**同时修掉一个上一轮埋下的坑**：`.hist2-body` 上的 `flex: 1` 去掉了。

- 现象：结果只有十几行时，body 被 `flex:1` 撑满 → 「模拟数据」标签被顶到视口最底部，
  表格和标签之间空出一大片（309px），看着像坏了。
- 原因：这条祖先链**只有内容比视口矮时才是 definite**（`.history-root{min-height:100dvh}`），
  此时 `flex:1` 才生效；内容比视口高时链是 indefinite、`flex:1` 无效。
  所以这个坑**只在小数据量时出现**，640 条时完全看不出来。
- 改法：去掉 `flex: 1`（保留 `min-height: 0`），让 body 按内容收缩，
  「表格 → 分页条 → 标签」贴在一起。实测 20 条时：表格 80→831、分页条 843→871、
  标签 883→910，剩余空白落在页面底部，符合常规表格页的观感。
- 注意：高度实测用的是 `body.top`（与 body 自身高度无关），所以去掉 `flex:1` 不影响测量。

回归（默认每页 20，640 条）：32 页；页码 `1,2,3,4,5,…,32`；
末页 `1,…,28,29,30,31,32`、下页禁用；跳页/改每页条数/查询回第 1 页 全部正常；
表格 751px、无页面滚动条。
